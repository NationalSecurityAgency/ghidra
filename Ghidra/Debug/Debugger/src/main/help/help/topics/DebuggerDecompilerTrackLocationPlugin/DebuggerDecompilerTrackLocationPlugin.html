Debugger: Tracked Location in the Decompiler

When active in the Debugger, the Decompiler marks the tracked location, usually the program counter, the same way the static listing does. The location is mapped from the current trace into the decompiled program using the Static Mappings. Each token generated from the instruction at that location is given the tracked-register background color, and each line containing one of those tokens has the tracked-register marker in the Debugger's margin. That margin is shared with the breakpoint markers. Keep in mind, the relationship between machine instructions and the decompiled code is not always so simple. One instruction may contribute to many lines, or to none at all. If the tracked location is not in the decompiled function, or it cannot be mapped to the program, nothing is marked.

These marks are independent of the Decompiler's cursor. They follow the debugger as it executes, while the cursor and its highlights remain under the user's control.

The location tracked is the same as in the primary Dynamic Listing, and is configured using its Track Location action. For example, if that listing tracks the stack pointer, or a watch expression, the Decompiler will mark that location instead. If it tracks nothing, the Decompiler marks nothing.
